# 分支策略

当前阶段 WatchMe 使用单主线开发：`main`。

## 为什么先用一个分支

- 项目还处于需求定稿和骨架搭建阶段，单分支更利于快速收敛。
- 历史调研只保留为分析文档，不参与 Git merge。
- 目前没有多人并行开发，不需要提前制造复杂分支结构。

## 工作规则

1. `main` 是唯一长期分支。
2. 新源码只写入 `refactor/`。
3. 历史分析文档只作参考，不把上游快照当作开发目录。
4. 文档、需求和架构调整直接提交到 `main`。
5. 只有出现较大实验时才创建短生命周期分支，例如：
   - `experiment/pixel-room`
   - `experiment/sse`
   - `agent/windows-rewrite`

实验完成后合回 `main`，然后删除实验分支。

## 提交约定

建议使用简洁前缀：

- `docs:` 文档
- `feat:` 新功能
- `fix:` 修复
- `refactor:` 结构调整
- `test:` 测试
- `build:` 构建和部署
