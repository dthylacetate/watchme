# WatchMe 产品需求文档

## 1. 产品简介

WatchMe 是一个面向个人使用的状态展示系统。它把电脑当前活动转换成隐私安全的公开状态，让朋友、访客或自己在网页上看到“现在大概在做什么”，但不会泄露聊天内容、邮箱、银行页面、文件路径等敏感信息。

产品形态：

- 桌面端 Agent：运行在 Windows/macOS，采集当前前台应用和辅助状态。
- 后端服务：接收上报、处理隐私、存储数据、提供 API。
- Web 仪表盘：公开展示当前状态和近期活动。

一句话目标：**展示存在感，不泄露生活细节。**

## 2. 用户与场景

目标用户：

- 想公开展示个人在线状态、当前工作/娱乐状态的人。
- 有 VPS、NAS、家用服务器或局域网部署环境的人。
- 关心隐私，不希望直接公开窗口标题和具体内容的人。

典型场景：

- 在个人主页上嵌入“我现在在做什么”。
- 给朋友看自己是否在线、是否正在忙。
- 回顾当天主要用过哪些应用。
- 在多台设备之间看当前活跃设备。

## 3. 产品原则

### 3.1 隐私优先

- 原始窗口标题默认不保存。
- 聊天、邮箱、金融、系统设置、文件管理等应用默认隐藏标题。
- 浏览器页面标题默认谨慎处理。
- 未知应用默认不展示标题，除非被用户加入允许列表。
- 健康数据、音乐数据等额外数据必须有明确开关。

### 3.2 本地和个人部署友好

- 默认 SQLite。
- 默认单服务部署。
- 开发期优先直接运行，不依赖 Docker。
- 生产期优先支持 VPS/systemd/Nginx/静态文件目录这类直接部署方式。
- Docker 仅作为可选打包方式，不作为 MVP 的主要开发路径。
- 不依赖云数据库或第三方队列。

### 3.3 可解释

- 用户应该能看懂为什么某个标题被隐藏或展示。
- 隐私规则可配置、可测试、可审计。
- API 字段命名清楚，公开数据和内部数据分开。

### 3.4 轻量实时

- MVP 可以使用轮询。
- 后续可升级到 SSE。
- 不为了“实时”引入过重架构。

## 4. MVP 功能需求

### 4.1 桌面 Agent

Windows Agent：

- 获取前台进程名和窗口标题。
- 检测用户 AFK。
- 检测音频播放和全屏状态，避免看视频/听音乐时误判 AFK。
- 获取电池百分比和充电状态。
- 识别常见音乐播放器的当前歌曲。
- 通过 Bearer Token 上报后端。
- 失败时指数退避重试。
- 提供基础托盘菜单：状态、配置、日志、退出。

macOS Agent：

- 获取前台应用名和窗口标题。
- 检测用户空闲时间。
- 检测音频播放和全屏状态。
- 获取电池状态。
- 识别 Spotify、Apple Music 等常见播放器。
- 通过 Bearer Token 上报后端。
- 提供菜单栏状态和退出入口。

Agent 配置：

```json
{
  "server_url": "https://example.com",
  "token": "device-token",
  "interval_seconds": 5,
  "heartbeat_seconds": 60,
  "idle_threshold_seconds": 300
}
```

### 4.2 后端服务

必须支持：

- `POST /api/report`：设备状态上报。
- `GET /api/current`：公开当前状态。
- `GET /api/timeline`：公开指定日期活动。
- `GET /api/config`：站点公开配置。
- `GET /api/health`：服务健康检查。

核心行为：

- Bearer Token 认证设备。
- 根据 token 绑定 `device_id`，不信任客户端自报设备身份。
- 解析应用名。
- 生成公开安全的 `display_title`。
- 原始 `window_title` 不入库。
- 用 HMAC 标题哈希做去重。
- 设备超过阈值未上报后标记离线。
- 定期清理旧数据。

### 4.3 Web 仪表盘

必须展示：

- 当前活跃设备。
- 当前公开状态描述。
- 设备列表及在线/离线状态。
- 今日活动列表或时间线。
- 每个应用的粗略使用时长。
- 离线状态。
- 加载、错误、空数据状态。

建议展示：

- 电池状态。
- 正在播放的音乐。
- 访客数。
- 日夜模式。

### 4.4 隐私规则

规则类型：

- `hide`: 不展示标题。
- `safe_title`: 展示处理后的标题。
- `app_only`: 只展示应用名。
- `allowlist`: 用户明确允许展示标题。

默认策略：

- 聊天、邮箱、金融、系统、文件、代理、会议：`hide`。
- 浏览器：敏感关键词隐藏，视频网站等可展示处理后的标题。
- IDE、视频、音乐、游戏、设计工具：可按规则展示处理后的标题。
- 未知应用：`app_only`。

必须有测试覆盖：

- 标题隐藏。
- 浏览器敏感关键词。
- 视频标题提取。
- 音乐标题提取。
- 未知应用默认策略。

## 5. 数据需求

### 5.1 设备状态

字段：

- `device_id`
- `device_name`
- `platform`
- `app_id`
- `app_name`
- `display_title`
- `last_seen_at`
- `is_online`
- `extra`

### 5.2 活动记录

字段：

- `id`
- `device_id`
- `app_id`
- `app_name`
- `display_title`
- `title_hash`
- `time_bucket`
- `started_at`
- `created_at`

禁止：

- 保存原始 `window_title`。

### 5.3 额外状态

MVP 支持：

- `battery_percent`
- `battery_charging`
- `music.title`
- `music.artist`
- `music.app`

健康数据不进入 MVP 默认范围。以后如支持，必须单独开关，并在公开页面明确说明。

## 6. 非功能需求

安全：

- 设备 token 不写入代码。
- 支持 token 轮换。
- API 有基础速率限制。
- 响应不暴露内部错误细节。

性能：

- 个人部署场景下，1-10 台设备、7-30 天数据保持流畅。
- 当前状态 API 响应目标低于 100ms。
- 时间线查询应避免全表扫描。

可靠性：

- 后端重启不丢数据。
- Agent 断网后自动恢复。
- 数据库迁移可重复执行。

可维护性：

- 前后端共享 API schema。
- 隐私规则独立模块。
- 数据库迁移有版本。
- 核心逻辑有测试。

## 7. 不做什么

MVP 不做：

- Android Agent。
- 多用户账号系统。
- 组织/团队功能。
- 公开原始窗口标题。
- 默认上传健康数据。
- AI 总结默认启用。
- 浏览器插件。

## 8. 成功标准

第一版完成时应满足：

- Windows Agent 能稳定上报。
- macOS Agent 能在实机验证后上报。
- 后端能作为常驻服务直接运行。
- 前端能构建为静态文件并由后端或 Nginx 提供。
- 前端能展示当前状态和今日活动。
- 隐私测试通过。
- 旧参考 API 中的核心上报格式可以兼容或有明确迁移说明。
